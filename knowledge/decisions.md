# Решения и причины

## Статический экспорт вместо SSR

`output: 'export'`. Портфолио — read-only контент без пользовательских данных,
GitHub Pages бесплатен и не умеет ничего, кроме статики. Отсюда же
`images: { unoptimized: true }`: оптимизатор Next требует рантайм, которого нет.

## `trailingSlash: true`

У GitHub Pages нет конфигурации редиректов, и единственный, что он делает сам, —
директория → директория со слешем. При `false` экспорт кладёт `portfolio.html`:
`/portfolio` работает, а `/portfolio/` отдаёт 404, и починить это нечем. При
`true` кладётся `portfolio/index.html`, `/portfolio/` отдаётся напрямую, а
`/portfolio` получает 301 — резолвятся обе формы.

## `html-beautify` в пайплайне сборки

`npm run build` после `next build` прогоняет `html-beautify` по `out/**/*.html`.
Экспорт Next минифицирует разметку в одну строку; форматирование делает диффы
собранного сайта читаемыми и позволяет глазами проверять результат.

## Три режима карточки вместо одного `<Link>`

`ProjectCard` умеет три состояния, режим задаётся данными:

1. обычная карточка → `<Link href="/portfolio/<id>">`;
2. `cardExternalLink` → `<a target="_blank" rel="noopener noreferrer">`, для
   проекта с живым продуктом, но без кейса (Netok → netok.app);
3. `inDevelopment` → `<div>`, некликабельно, с меткой «In development».

В третьем режиме с обёртки снимается класс `group`. Иначе карточка сохраняла бы
hover-подъём превью и перекраску заголовка — реакция на наведение без перехода
читается как сломанная ссылка.

Отдельное поле `cardExternalLink` заведено потому, что `externalLink` уже занят
кнопкой «Visit Website» в шапке кейса: у FormEngine есть и сайт, и кейс, одним
полем эти два случая не описать.

## Цикл анимации через перевешивание класса, а не `infinite`

`animation-iteration-count: infinite` учитывает `animation-delay` только на
первой итерации. Последовательность, где шаги имеют разные длительности,
начиная со второго цикла расползается по фазе. `AnimationObserver` вместо этого
снимает и возвращает `in-view` по периоду `--animate-cycle`, перезапуская всё с
нуля, — и задержки с длительностями остаются записаны обычными секундами.

## `fill-mode: backwards` в обложках

Transform, оставшийся на SVG-группе после анимации, удерживает поддерево на
композитном слое, который Chrome растеризовал один раз, и финальный кадр
выглядит замыленным. При `backwards` transform снимается по завершении, слой
отпускается, логотип рисуется резко (замер: примерно на 10% меньше полутоновых
пикселей на кромках). Побочный плюс — стартовые состояния описаны один раз, в
`from` кейфреймов.

## Прогрессивное улучшение обложек

Финальное состояние логотипа описано вне `@media (scripting: enabled)`, а
скрытие до `in-view` — внутри. С выключенным JS обложка показывает собранный
логотип вместо пустого блока.

## CSS обложек колокирован, а не вынесен в Tailwind

Кейфреймы обложек одноразовые, читают собственные custom properties (`from`/`to`
интерполируют `var()`, что в объекте кейфреймов Tailwind так же чисто не
записать) и требуют селекторов по потомкам, завязанных на `.in-view`. В общий
конфиг это добавило бы вес ради того, что ни один другой компонент не переиспользует.

## Награда iF Design как награда платформы

В карточке Pulse упоминания награды нет, в кейсе формулировка «платформа Pulse
получила iF Design Award 2022, я был одним из шести дизайн-лидов в команде из 25
дизайнеров». Награда командная, подавать её как личную — некорректно.

## Отказ от секции «Earlier work»

De Fonseca, Bud и KFC жили отдельной текстовой секцией архива внизу `/portfolio`.
После удаления Bud и KFC в ней остался один проект, а у De Fonseca есть
полноценная обложка — держать заголовок и подзаголовок ради одной карточки смысла
нет. Секция убрана, De Fonseca переехал в основную сетку, `archivedProjects` и
`archivedProjectIds` из `projects.ts` удалены.

## `Layout` без пропа `backgroundColor`

Раньше страницы прокидывали `backgroundColor="#FFFFFF"`, перебивая через
inline-style токен `--background` (он был `#FFF9F1`). Токен переведён на белый,
проп удалён — фон снова задаётся одним местом.
